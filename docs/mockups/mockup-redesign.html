Design Decisions
  • Remote Configuration uses tabs instead of one scrolling form. Connection/Auth/Performance are three distinct concerns — users shouldn't have to scroll past OIDC fields if they're just changing a bucket name.
  • OIDC fields are grouped in a bordered card that only appears when "OIDC / SSO" is selected as the auth method. If they choose "Named Profile" or "Access Keys", this card disappears entirely.
  • Settings page uses a left nav instead of stacked expansion panels. This is the Cloudscape pattern (split panel) and works better at scale — you always know where you are, and the page doesn't bounce around as panels expand/collapse.
  • "Appearance" section is new — this consolidates the current "UI Preferences" modal (notification position, auto-hide delay) into the main settings.
  • 2-column grid for related fields reduces vertical scroll. Bucket + Region are a natural pair. Session Duration + CA Bundle are a pair. Max Transfers + Max Checksums are a pair.
  • Pill-shaped buttons match Cloudscape's border-radius-button: 20px token. The filled primary button uses the Cloudscape primary-400 color.
  • Settings tabs are live in this mockup — click General / Transfers / Hot Folders / Reports / Logging / Appearance in the left nav to switch panels.
  • "Transfers" holds the default performance settings (Storage Class, Checksum Algorithm, Auto-tuning, Threads/Chunk size, Transfer Acceleration, File Order, Max Age, Metadata filter). These seed every new Remote Configuration, which can still override them per-profile on its own Performance tab. Open question: should these be global defaults, or live only on each Remote Configuration?

Design Rationale
  • Refresh stays in the overflow (not as a visible button) since the app auto-refreshes on changes. Manual refresh is a fallback.
  • New Folder / New Prefix is in the overflow rather than a persistent icon button — it's used occasionally, not every session.
  • Bucket Report is S3-only. It generates a detailed report of bucket contents — a power-user/admin action.
  • Hot Folder is Local-only. Sets up automatic uploads when files land in a folder — a core workflow for DITs.
  • Transfer Settings / Edit Remote Configuration provide quick access to the profile config without navigating to global preferences.
  • Favorite Paths gives Local users quick access to bookmarked directories.
  • The right-click context menu on individual items handles per-file actions (open, rename, delete). The ··· menu handles panel-wide actions.

Right-Click Menus — How the context menu relates to the ··· overflow menu

Recommendation: mirror, don't duplicate
They shouldn't be identical. Right-clicking an item shows item-scoped actions (Open, Rename, Delete, Upload). Right-clicking empty panel space shows the same panel-level list as the ··· menu. That "menu depends on where you click" behaviour is the Finder / File Explorer convention users already expect — and it keeps the ··· button as the discoverable, always-visible way to reach the same panel actions.

On the S3 panel
  • The item menu swaps Upload to S3 → Download, and Reveal in Finder becomes Copy S3 URI.
  • Rename and Delete only appear when the daemon's allowRemoteRenameDelete permission is on — otherwise they're hidden.
  • Empty-space mirrors the S3 ··· menu: New Prefix, Generate Bucket Report, Set Starting Prefix, Edit Remote Configuration.
Why not make them identical everywhere? A context menu that ignores what you clicked (showing "New Folder" when you right-click a file) feels broken. Scoping the menu to the target is what makes right-click feel native. The overlap is intentional and lives in one place: the empty-space menu = the ··· menu.
