Deleting S3 Prefix

After an S3 prefix deletion is requested, the deletion goes through two stages.

First, all versions of child objects in the prefix are discovered. During this stage, if any new objects are added to the prefix through transfers or external tools, they will be added to the list of object versions discovered for deletion. Next, all discovered object versions are deleted. If any new objects are added to the prefix in this stage, they will be not be deleted.

} @if (mode === 'rename-s3-prefix') {

Renaming S3 Prefix

Renaming an S3 prefix can take a long time since a rename can only be achieved by copying all child objects to the new prefix, then deleting all objects in the original prefix. While renaming is in progress, file browsers cannot be reloaded until the rename is complete to prevent new transfers from starting while a rename is in progress.

After an S3 prefix rename is requested, the rename goes through two stages.

First, all child objects in the prefix are discovered. During this stage, if any new objects are added to the prefix through transfers or external tools, they will be added to the list of objects discovered for renaming.

Next, for each discovered object, the latest version is first copied to the new name. If this is successfully, then all versions of the original object with the original name are discovered and permanently deleted. If the copy fails, then the deletion step doesn't happen, and the error is logged. If a new object is added to the original S3 prefix with the same name as an object to be copied, this new object will be the version of the object copied over to the new prefix. If a new object is added to the new S3 prefix with the same name as an object to be deleted before deletion is complete, it will be deleted.
